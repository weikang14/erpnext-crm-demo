# Design: Ombak Metal Works ERP (001-erp-factory)

## Why this exists

Portfolio piece for ERP implementation / support roles at manufacturers (SAP, Navision /
Business Central and ERPNext shops) and for roles that customise ERPNext in Python + Frappe.
The owner's work history is retail/F&B POS onboarding; this project proves they
understand a factory's order-to-delivery flow and can customise an ERP in code.

A CRM (Salesforce, contract 002) and the CRM <-> ERP integration (contract 003) come
after this contract and are out of scope here.

## The fictional company

**Ombak Metal Works Sdn Bhd**, Johor, Malaysia (currency MYR). Make-to-order sheet-metal
fabrication: customers send an order, the factory buys material if short, cuts, bends,
welds, powder-coats, inspects, and delivers on its own lorry.

- Finished goods (5): cable tray, machine guard, wall bracket, pallet rack upright,
  equipment base frame.
- Raw materials (~10): MS plate, GI sheet, angle bar, flat bar, welding wire,
  powder paint, bolts/nuts.
- Workstations (4): Laser Cutting, CNC Press Brake, Welding Bay, Powder Coating,
  each with an hourly cost.
- Warehouses: Raw Material, Work In Progress, Finished Goods, Rejected.

## Platform decision

ERPNext v16.37.0 (current stable) on Docker, based on frappe_docker's `pwd.yml`.
Rejected alternatives: writing an ERP from scratch (the target jobs implement packaged
ERPs, they don't hire people to write one); Odoo (not named by any target job);
D365 BC trial (expires in 30 days and needs a work email).

## What is standard ERPNext vs. what we write

| Area | How | Why |
|---|---|---|
| Company, items, BOM with operations, workstations, warehouses, customers, suppliers, QI templates, drivers/vehicles | Standard ERPNext, created by an idempotent setup script | Shows implementation/configuration skill; script makes the demo reproducible |
| Order -> production plan (MRP) -> material request -> PO -> receipt + QI -> work order -> job cards -> QI -> delivery -> trip -> invoice | Standard ERPNext doctypes, one month of demo transactions generated by script; every sales order goes through a Production Plan whose MRP raises the material requests | The flow employers ask about in interviews ("how does the system know what to buy?") |
| Defect Log + Defect Reason | Custom DocTypes in app `ombak_mfg` | ERPNext has no per-operation defect record with reason codes |
| 4 reports: Work Order On-Time Rate, Workstation Load, Operation Time Variance, Defect Pareto | Script Reports (Python + SQL) in `ombak_mfg` | The numbers a production manager actually reviews; proves Python + SQL |
| Daily overdue-work-order alert | Scheduler event in `ombak_mfg` -> Notification Log for Manufacturing Managers | Proves scheduler/background-job skill; visible in the bell icon |
| "Ombak Factory" workspace | Workspace JSON in `ombak_mfg` | One screen for the demo video |

## Architecture

```
ERP/
  docker-compose.yml   pwd.yml adapted: custom image, app bind-mounted for dev
  Dockerfile           FROM frappe/erpnext:v16.37.0 + pip install -e ombak_mfg
  apps/ombak_mfg/      Frappe app (bench new-app layout)
    ombak_mfg/hooks.py           scheduler_events, fixtures
    ombak_mfg/ombak_manufacturing/
      doctype/defect_reason/     master
      doctype/defect_log/        submittable record
      report/<4 reports>/
      workspace/ombak_factory/
    ombak_mfg/tasks.py           overdue work order alert
    ombak_mfg/setup/demo.py      idempotent master data + demo transactions
```

Two sites on the same bench: `localhost` (demo data, port 8080; named after the browser host so socket.io accepts the origin) and `test.localhost`
(tests only, so test records never pollute the demo).

## Defect Log rules

- Links a submitted, non-cancelled Job Card; work order, operation, workstation and
  item are fetched from it (read-only).
- `qty` must be > 0 and the total logged against one job card can't exceed that job
  card's completed quantity.
- Submittable; cancelled logs don't count in reports.

## Report definitions

- **On-Time Rate:** completed work orders in the date range; on time when
  `actual_end_date <= planned_end_date` compared by calendar day (finishing later the same
  day still counts as on time). Summary shows on-time % and average days late.
- **Workstation Load:** for a chosen week, scheduled minutes from ERPNext's capacity plan
  (`Job Card Scheduled Time`) in that week, divided by available minutes (workstation
  working hours x 6 days, default 8h/day). >= 90% is flagged as a bottleneck (capacity
  planning never schedules past 100%; it pushes work into later weeks).
- **Operation Time Variance:** completed job cards in range; standard minutes =
  work order operation `time_in_mins`, actual = job card `total_time_in_mins`;
  variance minutes and %.
- **Defect Pareto:** submitted Defect Logs in range grouped by reason, sorted by qty
  desc, with % and cumulative %; bar chart.

## Overdue alert

Daily job: submitted work orders not Completed/Stopped/Closed/Cancelled with
`planned_end_date` before today. One summary Notification Log per Manufacturing
Manager per day (no duplicates if the job runs twice); clicking it opens the work order
list filtered to the same overdue orders.
No email (the demo has no mail server).

## Language

UI, data and code in English (Malaysian employers' working language). The repo
README is bilingual (English + Chinese) and written at ship time.
